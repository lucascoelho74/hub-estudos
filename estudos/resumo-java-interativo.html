CLASSES E OBJETOS

Uma classe é a descrição de um conjunto de propriedades e comportamentos comuns (é um tipo). Um objeto é uma instância concreta dessa classe.

Forma geral (pseudocódigo, igual ao manuscrito):

classe <nome> : <superclasse> (<projeto>)
    <visibilidade>:
        <tipo> <atributo>
    <visibilidade>:
        <tipo> <metodo>
fim classe ! <nome> !

Em Java:

class Positivo {
    public int valor;
}   // fim classe Positivo

Instanciação e acesso:

Positivo p1 = new Positivo();   // sempre com new (não existe objeto na "stack")
p1.valor = 10;                  // acesso sempre por ponto (não existe ->)
Não há delete: quando nenhuma referência aponta mais para o objeto, o Garbage Collector o remove automaticamente.

ENCAPSULAMENTO

Restringe o acesso aos atributos e fornece métodos exclusivos para ler e alterar valores.

VisibilidadeQuem acessa
publicde qualquer lugar
privatesó a própria classe
protecteda classe e suas subclasses (e o mesmo pacote)

Regra prática: atributos private, métodos public.

Diferença de sintaxe para o C++: em Java o modificador vem antes de cada membro, não em blocos public: / private:.

class Componente {
    private int valor;    // modificador por membro
    private int erro;

    public void atribuir(int novo) { ... }
}
4

GETTERS E SETTERS

  • Utilizados para validar dados antes de gravar.
  • O this do Java é útil para dar ênfase ou desfazer ambiguidade quando o parâmetro tem o mesmo nome do atributo (mesma ideia do this do C++).
class Componente {
    private int valor;
    private int erro;

    public void atribuir(int novo) {
        int result = 0;                 // padrão da disciplina (aqui só ilustra o fluxo)
        if (novo > 0) {
            this.valor = novo;          // Java usa this.  (ponto), não this->
            this.erro  = 0;
        } else {
            this.valor = 0;
            this.erro  = 1;
        }   // fim if
    }   // fim atribuir

    public int extrairValor() {
        int result = this.valor;
        return result;
    }   // fim extrairValor
}   // fim classe Componente

get/set padrão:

public double getSalario()               { return salario; }        // sem parâmetro
public void   setSalario(double salario) { this.salario = salario; } // void, recebe novo

CONSTRUTORES E SOBRECARGA

Construtor:

  • Método que tem sempre o mesmo nome da classe.
  • Chamado na instanciação (new), para inicializar o objeto.
  • Sem tipo de retorno (nem void).
  • É sempre público.

Sobrecarga de construtores: permitida quando as listas de parâmetros são distintas (em quantidade e/ou tipo).

class Positivo {
    private int valor;
    private int erro;

    // ex1: construtor padrão
    public Positivo() {
        this.valor = 0;
        this.erro  = 0;
    }   // fim Positivo

    // ex2: construtor parametrizado
    public Positivo(int inicial) {
        this.valor = inicial;
        this.erro  = 0;
    }   // fim Positivo

    // ex3: construtor de cópia (em Java feito "na mão" — ver seção 10)
    public Positivo(Positivo inicial) {
        this.valor = inicial.valor;
        this.erro  = inicial.erro;
    }   // fim Positivo
}   // fim classe Positivo

**static (membros estáticos):**

  • Chamados sem instanciar objeto (ex.: MyIO.println(...), Math.pow(...)).
  • Um atributo estático é compartilhado por todos os objetos (uma única cópia).
  • Métodos estáticos só acessam membros estáticos.
class Ponto {
    static int nextID = 0;   // compartilhado
    int id;
    public Ponto() { id = nextID++; }   // cada objeto recebe um id único
}

Definição
Sobrecarga (*overload*)vários métodos de mesmo nome com listas de parâmetros diferentes, na mesma classe

// Sobrecarga: mesma classe, parâmetros diferentes
double dist(Ponto p)            { ... }
double dist(double x, double y) { ... }

// Sobrescrita: subclasse redefine método da superclasse
class Cachorro extends Animal {
    @Override
    public String falar() { return "Au au"; }   // @Override documenta a intenção
}

HERANÇA

Agrupar o que é comum numa superclasse e reaproveitar nas subclasses.

Notação: em Java usa-se extends (no lugar do : do C++).

class Sub extends Super { ... }

Três formas (iguais ao manuscrito):

FormaO que faz
Especificação (interface)a superclasse descreve o que a subclasse deve conter, não adiciona nada
Extensão (herança escrita)a subclasse acrescenta atributos ou métodos à definição original
Combinação (herança polimórfica)herda a interface e redefine ou introduz novos elementos
class Animal {
    protected String nome;

    public Animal(String nome) { this.nome = nome; }

    public String falar() {
        String result = "...";
        return result;
    }   // fim falar
}   // fim classe Animal

class Cachorro extends Animal {
    public Cachorro(String nome) {
        super(nome);            // super(...) chama o construtor da superclasse
    }   // fim Cachorro

    @Override
    public String falar() {
        String result = "Au au";
        return result;
    }   // fim falar
}   // fim classe Cachorro
  • super(...) → chama o construtor da superclasse.
  • super.metodo() → chama a versão da superclasse de um método sobrescrito.
  • Obs: a classe Exception faz o papel da "classe Erro" — é a superclasse de onde se herda o tratamento de erro (ver seção 14).
8

POLIMORFISMO

Classes derivadas invocam métodos de mesma assinatura da classe original, mas com comportamentos diferentes, especializados em cada uma e abstraídos dos detalhes internos.
Animal[] animais = new Animal[2];
animais[0] = new Cachorro("Rex");
animais[1] = new Gato("Mimi");

for (int x = 0; x < animais.length; x = x + 1) {
    MyIO.println(animais[x].falar());   // cada um responde do seu jeito
}   // fim for

Diferença para o C++: em Java todo método é virtual por padrão — não precisa da palavra virtual. Para impedir a sobrescrita, usa-se final. Para exigir que a subclasse implemente, usa-se abstract (método sem corpo em classe abstract).

abstract class Forma {
    public abstract double area();   // método abstrato: subclasse é obrigada a implementar
}

MEMÓRIA E REFERÊNCIAS

Em Java, toda variável de array ou de objeto é uma referência (ponteiro): guarda o endereço onde o conteúdo está, não o conteúdo em si.

int[] vet = new int[5];   // vet guarda o ENDEREÇO do array, não os 5 valores
Cliente c = new Cliente(); // c guarda o ENDEREÇO do objeto, não o objeto

Vocabulário (equivalências com o manuscrito de ponteiros):

C++Java
new Contato() cria na heap e devolve endereçoigual — mas tudo vai para a heap
p3->getNome()p3.getNome() (sempre ponto)
*ponteiro (objeto apontado)não existe desreferência explícita
if (p != nullptr)if (c != null)
delete pnão existe — Garbage Collector
using ref_Contato = Contato*não se aplica

Aliasing (dois nomes para o mesmo objeto):

Cliente c1 = new Cliente(1, "aa");
Cliente c2 = c1;            // c2 recebe O ENDEREÇO de c1 (NÃO é cópia!)
c2.setCodigo(3);
// c1 e c2 mostram (3,"aa") — é o MESMO objeto

**Pegadinha clássica — == entre objetos compara ENDEREÇOS:**

Hora h1 = new Hora(12, 30, 30);
Hora h2 = new Hora(12, 30, 30);
if (h1 == h2)  ...            // FALSO: são dois new -> endereços diferentes
// Para comparar CONTEÚDO, escreve-se um método equals()

CÓPIA DE OBJETO — clone()

Reserva área nova e copia valor por valor. Serve para criar um novo objeto duplicando os dados do original.

Em C++ isso era o construtor de cópia. Em Java, como c2 = c1 só cria alias, a cópia de verdade é feita por um método clone():

public Cliente clone() {
    Cliente result = new Cliente();   // objeto novo (endereço novo)
    result.codigo = this.codigo;      // copia campo a campo
    result.nome   = this.nome;
    return result;
}   // fim clone
  • c2 = c1 → alias (mesmo objeto).
  • c2 = c1.clone() → cópia (objetos distintos, mesmos atributos).
  • Em laços: vet[i] = c1.clone() cria um objeto novo por posição; vet[i] = c1 faria todas as posições apontarem para o mesmo objeto.
Java não tem a "Regra dos Três" do C++ (destrutor / construtor de cópia / operator=), porque não há destrutor nem sobrecarga de =. O que resta do conceito é: se o objeto tem referências internas, o clone() precisa clonar essas referências também (senão vira cópia rasa).

PASSAGEM DE PARÂMETROS

Java (como C) tem sempre passagem por valor. O detalhe é o que está no "valor":

  • Tipo primitivo → copia o valor; alterações no método não saem.
static void alterar(int a) { a = 10; }   // não muda o original
  • Array/objeto → o valor copiado é o endereço. Então: 1. dá para alterar o conteúdo da área (a alteração "sai" do método); 2. mas reapontar o parâmetro (b = new int[5]) não afeta quem chamou.
static void mexer(int[] b) {
    for (int i = 0; i < b.length; i++) b[i] *= 5;  // ALTERA o array original
    b = new int[5];                                 // só a cópia local reaponta
}

OPERADORES E EXPRESSÕES (não há sobrecarga)

Java não permite sobrecarga de operadores. Onde no C++ você faria operator==, operator+, operator[], em Java você escreve métodos comuns.
Intenção (C++)Em Java
operator==método boolean equals(Object o)
operator+método Array somar(Array outro)
operator[]array[i] já existe para arrays; em classe própria vira get(i)/set(i)
operator=não há — = sempre copia a referência

Operadores da linguagem:

+  -  *  /  %          // aritméticos (32/3 = 10 inteiro; 32%3 = 2)
== != < > <= >=        // relacionais
&& || !                // lógicos  (equivalem a AND/OR/NOT da disciplina)
++ --                  // x++ usa e depois incrementa; ++x incrementa antes

Comparação de conteúdo (o "operator==" traduzido):

public boolean equals(Array outro) {
    boolean result = false;

    if (length == outro.length) {
        result = true;

        int x = 0;
        while (x < length && result) {          // sem break, com flag result
            result = result && (data[x] == outro.data[x]);
            x = x + 1;
        }   // fim while
    }   // fim if

    return result;
}   // fim equals

GENERICS (o "template" do Java)

Um generic é uma classe onde você define a lógica uma vez e o tipo concreto é escolhido só na hora de criar o objeto. É o equivalente Java dos templates de C++.
class Array<T> {                 // <T> no lugar de template<typename T>
    private int length;
    private T[] data;

    // ...
}   // fim classe Array

Uso:

Array<Integer> a = new Array<>();
Array<Double>  b = new Array<>();
Array<String>  c = new Array<>();

Diferenças importantes para o C++:

  • Generics só aceitam tipos-referência (Integer, Double, String), não primitivos (int, double) → usa-se o *wrapper* correspondente.
  • Não existe separação .hpp/.cpp: tudo fica no mesmo .java.
  • Não é preciso o "Obs: templates ficam no .hpp" do C++ — em Java não há essa regra.

TRATAMENTO DE EXCEÇÕES

Além de atributos e métodos, toda classe deveria ter seu próprio tratamento de erro e o seu construtor padrão para ser instanciada.

Exceção = evento que ocorre na execução e desvia o fluxo normal (divisão por zero, arquivo inexistente, índice inválido → ArrayIndexOutOfBoundsException, etc.).

try / catch / finally:

try {
    // código que pode falhar; ao dar exceção, ESTE bloco para na hora
} catch (ClasseDaExcecao e) {
    // executado só se houver a exceção
} finally {
    // executado SEMPRE (tenha havido exceção ou não) — ideal para "limpeza"
}

Múltiplos catch (um por tipo de exceção):

try {
    Integer i = Integer.valueOf(args[0]);
} catch (NumberFormatException e) {
    MyIO.println("Erro de formatacao!");
} catch (ArrayIndexOutOfBoundsException e) {
    MyIO.println("Erro na passagem de parametros!");
} finally {
    MyIO.println("FIM DE PROGRAMA!");
}   // fim try

Os três nomes parecidos:

PalavraOnde apareceFunção
try/catch/finallycorpo do métodotratar a exceção aqui
throwsassinatura do métodorepassar a responsabilidade a quem chamou
throwcorpo do métodolançar (criar) uma exceção
// throws: repassa
public void metodo() throws Exception { ... }

// throw: lança
public static void metodo(int i) throws Exception {
    if (i % 2 == 1) {
        throw new Exception("Valor impar");
    }   // fim if
}   // fim metodo

Herança de erro (o "obs" do manuscrito): a classe Exception é uma superclasse; para criar um erro próprio, herda-se dela.

class ErroIndice extends Exception {
    public ErroIndice() {
        super("Indice fora dos limites");   // manda a mensagem para a superclasse
    }   // fim ErroIndice
}   // fim classe ErroIndice

INTERFACES

Uma interface define e padroniza como classes distintas interagem, sem especificar detalhes de implementação. Quem assina o contrato (implements) é obrigado a implementar todos os métodos — ou declarar a classe abstract.

É a "Especificação (interface)" da seção de herança, formalizada:

public interface Autenticavel {
    public abstract boolean autentica(int senha);   // sem corpo
}

class Gerente extends Funcionario implements Autenticavel {
    private int senha;
    public boolean autentica(int senha) {
        return this.senha == senha;                  // implementa o contrato
    }
}
  • Atributos de interface são implicitamente públicos, estáticos e finais (constantes).
  • Métodos são públicos e abstratos.
  • O poder: um método pode receber qualquer objeto que implemente a interface (void login(Autenticavel a)), sem saber a classe concreta — polimorfismo puro.

ENTRADA E SAÍDA (MyIO)

Na disciplina usa-se a classe MyIO (evita as limitações de Scanner e BufferedReader). Métodos públicos e estáticos — chama-se MyIO.metodo() sem instanciar.

String str  = MyIO.readString("Entre com uma palavra: ");
int    i    = MyIO.readInt("Entre com um inteiro: ");
double real = MyIO.readDouble("Entre com um real: ");

MyIO.println("Resultado: " + i);
  • Escrita: print, println, printf, pause.
  • Leitura: readInt, readDouble, readString, readLine, readChar, readBoolean.

**Concatenação com +** — cuidado clássico:

"soma: " + 2 + 3      // -> "soma: 23"  (concatena)
"soma: " + (2 + 3)    // -> "soma: 5"   (parênteses somam antes)

Redirecionamento (como o corretor testa): MyIO/System.out escrevem no dispositivo padrão, trocável no terminal:

java Programa < entrada.txt > saida.txt

ARRAYS E STRINGS

Arrays:

int[] vet = new int[n];        // recém-criado começa ZERADO
double[][] matriz = new double[10][20];

for (int i = 0; i < vet.length; i = i + 1) {   // .length (sem parênteses!)
    vet[i] = MyIO.readInt();
}   // fim for
  • Índices de 0 a n-1; fora disso → ArrayIndexOutOfBoundsException.
  • vet.length é atributo (array); str.length() é método (String).

Strings (funcionam como vetor de caracteres, mas imutáveis):

str.charAt(pos)    // caractere da posição (NÃO existe charSet: String não muda in place)
str.length()       // tamanho
str.equals(outra)  // compara CONTEÚDO (== compararia endereço!)
str.substring(0,2)
Integer.parseInt("42")   // String -> int
String.valueOf(42)       // int -> String

RECURSIVIDADE

Um método é recursivo quando chama a si mesmo. Precisa de:

  1. Chamada recursiva (problema menor);
  2. Condição de parada (caso base).
int fatorial(int n) {
    int result = 1;
    if (n > 1) {
        result = n * fatorial(n - 1);   // chamada recursiva
    }   // fim if  (n == 1 -> para)
    return result;
}   // fim fatorial
  • Cada chamada tem suas próprias variáveis locais (empilhadas); ao terminar, o estado anterior é recuperado.
  • Pode ser direta (A chama A) ou indireta (A chama B que chama A).
  • Fibonacci recursivo puro é ineficiente (recalcula subproblemas); a versão iterativa é bem mais rápida.

TADs NATIVOS (List, Stack, Queue)

Onde no C++ você implementava célula / pilha / fila na mão, Java já fornece prontos (todos usam generics):

**List — ArrayList, Vector, LinkedList** (implementam a interface List):

CaracterísticaArrayList / VectorLinkedList
Implementaçãoarray redimensionávellista duplamente encadeada
get(index)eficienteineficiente
Inserir/remover no meioineficienteeficiente
  • Vector é sincronizada (threads); sem threads, ArrayList é mais rápida.

Stack (pilha — LIFO):

Stack<String> pilha = new Stack<String>();
pilha.push("A");            // empilha
pilha.push("B");
while (pilha.empty() == false) {
    MyIO.println(pilha.pop());   // desempilha: sai B, depois A (ordem inversa)
}   // fim while

Métodos: push, pop, peek (vê o topo sem remover), empty, search.

Queue (fila — FIFO): é uma interface, instancia-se com LinkedList:

Queue<String> fila = new LinkedList<String>();
fila.add("A");
fila.add("B");
while (fila.isEmpty() == false) {
    MyIO.println(fila.remove());  // sai na MESMA ordem: A, depois B
}   // fim while

Métodos: add/offer (insere), remove/poll (remove a cabeça), element/peek (consulta a cabeça sem remover).
