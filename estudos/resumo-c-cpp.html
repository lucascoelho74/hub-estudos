ED02–03

Fundamentos de C & algoritmos

Do problema ao algoritmo pronto, e a sintaxe essencial de C: tipos, estrutura sequencial, condicionais (ED02) e repetições (ED03).

🏗️ As duas preocupações

Estrutura de dados: como representar as entidades do problema. Estrutura lógica: a sequência e a necessidade dos processos que operam sobre esses dados. (Ver o Roteiro para elaboração de algoritmos da apostila.)

🔁 Fluxo de controle

Um algoritmo não é só texto (estático) — ele exprime ações (dinâmico), coordenadas por sequência, seleção (if) e repetição (for/while).

📥 I/O do curso

Da io.h: IO_printf, IO_readint, IO_readDouble, IO_pause, IO_id. Evita mexer direto com scanf.

🔢 Tipos

int, double, char. Strings em C são vetores de char terminados em '\0'.

🧱 Macros AND/OR/NOT

#define AND && — deixa a condição lida como texto: if (a > 0 AND b > 0).

📐 Escolha do laço (regra do curso)

for — quando sei quantas vezes

Iteração contada: percorrer um vetor de N posições, repetir K vezes. O limite é conhecido de antemão.

while — quando é condição lógica

Repetir enquanto algo for verdade: ler arquivo até acabar, procurar até achar. Substitui o break proibido.

ED04–05

Abstração: funções & procedimentos

ED04–05 — empacotar lógica em funções (retornam valor) e procedimentos (só executam ações), na forma iterativa.

Função vs. procedimento — padrão do curso
// FUNCAO: retorna um valor, um unico return via 'result'
int somar ( int a, int b )
{
  int result = a + b;
  return result;
} // end somar

// PROCEDIMENTO: nao retorna (void), so executa acoes
void mostrarLinha ( int n )
{
  for ( int x = 0; x < n; x = x + 1 )
  {
    IO_printf ( "*" );
  } // end for
} // end mostrarLinha

📤 Passagem por valor

A função recebe uma cópia. Alterar o parâmetro não muda o original. Bom para valores simples.

🔗 Passagem por referência (ponteiro)

A função recebe o endereço (int *p). Alterar *p muda o original. Necessário para modificar o dado do chamador.

ED06

Recursividade

ED06 — funções e procedimentos recursivos: uma função que chama a si mesma. Todo problema recursivo precisa de um caso base e um caso recursivo.

🛑 Caso base

A condição de parada. Sem ele, a recursão nunca termina → estouro de pilha (stack overflow).

♻️ Caso recursivo

A função se chama com um problema menor, caminhando em direção ao caso base.

Fatorial — o exemplo clássico
int fatorial ( int n )
{
  int result = 1;
  if ( n <= 1 )        // caso base
  {
    result = 1;
  }
  else                  // caso recursivo
  {
    result = n * fatorial ( n - 1 );
  }
  return result;
} // end fatorial

💡 Truque de ordem

Onde você coloca a chamada muda a ordem da saída. Imprimir antes da chamada → ordem decrescente/descida. Imprimir depois da chamada → ordem crescente/subida (o famoso "chamada antes do print").

ED07

Arquivos (I/O)

ED07 — persistir dados em .TXT: ler e gravar. O padrão do professor: um valor por linha. Fechar o arquivo é indispensável para gravar.

C — FILE*

FILE* f = fopen ( "DADOS.TXT", "r" );
if ( f == NULL ) { /* erro */ }
else {
  fscanf ( f, "%d", &x );
  fclose ( f );
}

Gravar (writeInts do ED07)

FILE* arq = fopen ( fileName, "wt" );
for ( y = 1; y <= x; y = y+1 )
{
  fprintf ( arq, "%d\n", y );
}
fclose ( arq );  // INDISPENSAVEL

🚨 Erro de runtime mais comum

Compila limpo mas quebra ao rodar → quase sempre o arquivo de entrada não existe (DADOS.TXT). Sempre teste if (f == NULL) antes de usar.

📖 Ler até acabar

Use while com a condição de leitura: while (fscanf(f,"%d",&x) == 1) ou while (!feof(f)). Nunca break — a própria condição encerra.

ED08–09

Grupos homogêneos: arranjos, matrizes, strings

ED08 (arranjos/vetores unidimensionais) e ED09 (matrizes) — coleções de elementos do mesmo tipo, acessadas por índice.

📊 Arranjo (vetor)

Sequência de N elementos do mesmo tipo. Índice de 0 a N-1. Comprimento = n.

🔲 Matriz

Arranjo bidimensional: m[linha][coluna]. Percorrida com for aninhado. Na passagem, informar linhas, colunas e a matriz.

🔤 String

Vetor de char terminado em '\0'. O terminador é o que marca o fim.

Percorrer um vetor e achar o maior (ED08)
int acharMaior ( int v[], int n )
{
  int maior = v[0];              // referencia inicial
  for ( int x = 1; x < n; x = x + 1 )
  {
    if ( v[x] > maior )
    {
      maior = v[x];
    }
  } // end for
  return maior;
} // end acharMaior
Matriz com for aninhado (ED09)
for ( int i = 0; i < linhas; i = i + 1 )
{
  for ( int j = 0; j < colunas; j = j + 1 )
  {
    IO_printf ( "%d ", m[i][j] );
  } // end for j
  IO_printf ( "\n" );
} // end for i

⚠️ Cuidado com a referência inicial

Ao buscar maior/menor, inicialize com o primeiro elemento válido (v[0]), não com 0. Se o vetor tiver só negativos, começar em 0 dá resposta errada.

ED10

Grupos heterogêneos: structs & ponteiros

ED10 — juntar dados de tipos diferentes numa unidade (struct), e acessá-los por endereço (apontador), em C.

Definir uma struct com typedef
typedef struct
{
  int h;
  int m;
  int s;
} Tempo;

typedef Tempo* ref_Tempo;   // tipo apontador

🎯 Os três operadores

&
endereço-de
&x = "onde x mora"
*
desreferência
*p = "valor lá"
->
membro via ponteiro
p->h = (*p).h

🧠 A regra de ouro do acesso

Variável usa ponto: t.h.  Ponteiro usa seta: p->h. A seta é só um atalho para (*p).h — os parênteses são obrigatórios pela precedência.

Passar ref_Tempo para uma função evita copiar a struct inteira e permite alterar o original.

Alocação dinâmica
// em C
ref_Tempo p = ( ref_Tempo ) calloc ( 1, sizeof ( Tempo ) );
// ... usar p ...
free ( p );

// em C++
Tempo* q = new Tempo;
delete q;
ED11–12

Templates (tipos genéricos)

ED11–12 — escrever uma classe que funciona para qualquer tipo, sem reescrever para int, double etc. São os cabeçalhos myarray.hpp e mymatrix.hpp.

📦 Array<T> · myarray.hpp

Vetor genérico do curso (ED11). Array<int>, Array<double> — um só código serve a todos.

🔲 Matrix<T> · mymatrix.hpp

Matriz genérica (ED12). Mesma ideia em duas dimensões.

Definição com template
template <typename T>
class Array
{
  private:
    T* dados;
    int comprimento;
  public:
    Array ( int n, T inicial );
    T get ( int i );
    void set ( int i, T v );
}; // end class Array
to_string com while (padrão do professor)
string Array::to_string ( )
{
  string result = "";
  int x = 0;
  while ( x < comprimento )
  {
    result = result + std::to_string ( dados[x] ) + " ";
    x = x + 1;
  } // end while
  return result;
} // end to_string

🏛️ Classe vs. Objeto

Classe é o molde (o tipo). Objeto é a instância — a variável criada a partir da classe. Uma classe Fracao; um objeto Fracao f(1,2);.

−
private
só dentro da classe
+
public

#
protected
classe + derivadas

⭐ Os 5 padrões universais de prova

  • Construtor padrão — sem parâmetros, inicializa em valores neutros
  • Construtor parametrizado — com new e cópia elemento a elemento
  • Setter com restrição — um if que valida antes de atribuir
  • to_string — while concatenando numa string
  • save() — grava em arquivo, um valor por linha
Anatomia de uma classe
class Fracao
{
  private:
    int numerador;          // atributos = estado interno
    int denominador;

  public:
    Fracao ( );               // construtor padrao
    Fracao ( int n, int d );  // construtor parametrizado
    int getNumerador ( );      // getter
    void setNumerador ( int n );// setter com restricao
    string to_string ( );     // saida formatada
}; // end class Fracao
Os dois construtores
// padrao: estado neutro
Fracao::Fracao ( )
{
  numerador = 0;
  denominador = 1;
} // end Fracao

// parametrizado: recebe e valida
Fracao::Fracao ( int n, int d )
{
  numerador = n;
  if ( d != 0 )
  {
    denominador = d;
  }
  else
  {
    denominador = 1;
  }
} // end Fracao
Herança & polimorfismo

Sobrecarga (overload)

Mesmo nome, assinaturas diferentes na mesma classe. Ex.: dois construtores. Resolvido em tempo de compilação.

Sobrescrita (override)

A derivada redefine um método da base. Com virtual, resolvido em tempo de execução → polimorfismo.

Sintaxe de derivação
class Fracao : public Erro
{
  private:
    int numerador;
  public:
    int getNumerador ( );
}; // end class Fracao

🔧 Rule of Three

Se sua classe aloca memória com new, ela precisa dos três: destrutor (~Classe()), construtor de cópia e operador de atribuição (operator=). Senão, cópias compartilham o mesmo ponteiro e dá double-free.

ED13–14

Tratamento de erros & exceções

ED13 define a classe Erro (Erro.hpp); ED14 usa herança dela e exceções — em vez de código de erro, lançar uma exceção e capturá-la mais acima.

try — tenta throw — lança catch — captura
Classe Erro (base para tratamento) — ED13
class Erro
{
  private:
    int erro;                 // codigo de erro (0 = sem erro)
  protected:
    void setErro ( int codigo ) { erro = codigo; }
  public:
    int getErro ( ) { return erro; }
}; // end class Erro
Lançar e capturar
int IntStack::pop ( )
{
  int result = 0;
  if ( topo == nullptr )
  {
    throw Erro ( 1 );   // pilha vazia
  }
  else
  {
    result = topo->getValor ( );
    // ... remover topo ...
  }
  return result;
} // end pop

// no chamador:
try { x = pilha.pop ( ); }
catch ( Erro& e ) { IO_printf ( "Erro %d\n", e.getErro ( ) ); }
ED15

Apontadores: Pilha & Fila

ED15 — o conteúdo mais recente. Células ligadas por apontadores, sem tamanho fixo. Pilha (LIFO) e Fila (FIFO), com tratamento de erro e sem break.

🔗 A célula (nó)

Cada célula guarda um valor e um apontador para a próxima. Ligando células, formamos uma estrutura que cresce e encolhe em tempo de execução.

Célula encadeada
class IntCell
{
  private:
    int valor;
    IntCell* proxima;   // apontador para o proximo no
  public:
    IntCell ( int v ) { valor = v; proxima = nullptr; }
    int getValor ( ) { return valor; }
    IntCell* getProxima ( ) { return proxima; }
    void setProxima ( IntCell* p ) { proxima = p; }
}; // end class IntCell

🥞 Pilha — LIFO

Last In, First Out. O último a entrar é o primeiro a sair. Insere e remove sempre no topo.

push (empilha) · pop (desempilha) · dup · swap

🚶 Fila — FIFO

First In, First Out. O primeiro a entrar é o primeiro a sair. Insere no fim, remove do início.

push/enqueue (final) · pop/dequeue (início) · compare · join · search

push — empilhar (insere no topo)
void IntStack::push ( int v )
{
  IntCell* nova = new IntCell ( v );
  nova->setProxima ( topo );  // nova aponta pro antigo topo
  topo = nova;                // topo passa a ser a nova
} // end push
pop — desempilhar (remove o topo, com exceção)
int IntStack::pop ( )
{
  int result = 0;
  if ( topo == nullptr )
  {
    throw Erro ( 1 );       // pilha vazia
  }
  else
  {
    IntCell* aux = topo;
    result = topo->getValor ( );
    topo = topo->getProxima ( );  // avanca o topo
    delete aux;                 // libera a celula removida
  }
  return result;
} // end pop
Fila — enqueue insere no fim
void IntQueue::enqueue ( int v )
{
  IntCell* nova = new IntCell ( v );
  if ( inicio == nullptr )   // fila vazia
  {
    inicio = nova;
    fim = nova;
  }
  else
  {
    fim->setProxima ( nova );  // liga no fim
    fim = nova;                // atualiza o fim
  }
} // end enqueue

🧹 Não esqueça o delete

Toda célula criada com new precisa de delete ao remover — senão, memory leak. No destrutor, esvazie a estrutura inteira.

⚠️ Sempre teste o vazio

Antes de pop/dequeue/consultar, cheque se está vazia (== nullptr) e lance Erro. É o caso de borda que o professor sempre cobra.
