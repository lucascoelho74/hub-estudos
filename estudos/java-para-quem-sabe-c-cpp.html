1

A GRANDE DIFERENÇA: COMPILAÇÃO E JVM

Em C/C++ o compilador gera código de máquina direto (executável nativo, só roda naquela plataforma). O Java faz em dois passos:

Programa.java  --(javac)-->  Programa.class (bytecode)  --(java/JVM)-->  execução
  • javac Programa.java gera bytecode (.class), não código nativo.
  • java Programa inicia a JVM, que interpreta o bytecode → "escreva uma vez, execute em qualquer lugar".
  • Trade-off: portável, porém mais lento que nativo.
  • O JIT (Just-In-Time) compila os trechos "quentes" para nativo em tempo de execução para acelerar.
2

ESTRUTURA MÍNIMA DE UM PROGRAMA

Não existe função solta como em C: tudo fica dentro de uma classe.
class ExemploEscrever1 {
    public static void main(String[] args) {
        System.out.println("Alo pessoal!!!");
    }
}

O que muda em relação a C/C++:

  • O arquivo tem o mesmo nome da classe: ExemploEscrever1.java.
  • Não tem #include, #define nem preprocessador. Usa-se import java.util.*;
  • Sem ponteiros * e &, sem malloc/free, sem cabeçalho .h.
  • Entrada sempre em public static void main(String[] args) (com String[], não int argc, char* argv[]).
  • Compilar: javac Arquivo.java → executar: java Arquivo (sem extensão).
3

TIPOS PRIMITIVOS (tamanhos FIXOS, ao contrário de C)

Em C o tamanho depende da máquina/compilador. Em Java é sempre o mesmo:

TipoTamanhoObservação vs C
boolean1 bittipo próprio true/false — não é int (em C, 0/≠0)
char16 bitsUnicode, não 8 bits ASCII
byte8 bitsinteiro
short16 bitsinteiro
int32 bitssempre 32, não varia
long64 bitsinteiro
float32 bitsreal
double64 bitsreal
  • Não existe unsigned.
  • if (x) só aceita boolean — não dá para usar int como condição (if (n) não compila).
4

SAÍDA E ENTRADA (muda tudo)

Não tem printf/scanf como padrão. Saída:

System.out.println("Alo" + " pessoal");   // + concatena
System.out.println("Inteiro: " + 13);      // converte automatico
System.out.println("x+y: " + (x+y));       // parenteses p/ somar antes!
Pegadinha: "soma: " + 2 + 3 dá soma: 23; "soma: " + (2 + 3) dá soma: 5.

Entrada com Scanner (ou, na disciplina, a classe MyIO):

import java.util.*;
Scanner sc = new Scanner(System.in);
int n = sc.nextInt();

// MyIO (metodos estaticos, nao precisa instanciar):
int x = MyIO.readInt("Digite: ");
String s = MyIO.readString();
MyIO.println("Resultado: " + x);

Redirecionamento (igual a C no shell): println escreve na saída padrão e readInt lê da entrada padrão — não necessariamente tela/teclado.

java Programa < in.txt > out.txt
5

OPERADORES E CONTROLE — idênticos a C

Aqui você não precisa reaprender nada. São iguais a C/C++:

+ - * / %              // aritméticos
++ --                  // pré/pós incremento
<< >> & | ^ ~            // bit a bit
? :                    // ternário
if / else  while  do-while  for  switch / case / break / default
  • Divisão inteira trunca (32/3 = 10).
  • % (resto) só funciona em inteiros.
6

ARRAYS (o que muda)

int[] vet = new int[10];   // aloca com new, nao malloc
  • Alocação com new, sem malloc/sizeof/free (o garbage collector limpa).
  • Array recém-criado vem zerado automaticamente.
  • Tem checagem de limites: índice inválido lança ArrayIndexOutOfBoundsException (em C daria lixo/segfault).
  • Tamanho via vet.length (atributo, sem parênteses).
  • Sintaxe int[] v ou int v[], as duas valem.
7

STRINGS (não é char*)

String é uma classe, imutável. Não é vetor de char terminado em \0.
str.length()    // tamanho (metodo, com () - diferente de array!)
str.charAt(i)   // caractere na posicao i
// NAO existe str[i] nem alterar posicao a posicao
  • Nada de strlen/strcpy/strcmp.
  • Para comparar conteúdo use .equals(), nunca == (== compara endereço).
8

PONTEIROS → REFERÊNCIAS (conceito central)

Java não tem ponteiros explícitos, mas toda variável de objeto ou array é uma referência (guarda o endereço, não o conteúdo).

Cliente c1 = new Cliente(1, "aa");
Cliente c2 = c1;      // ALIAS: c2 aponta pro MESMO objeto (nao copia!)
c2.setCodigo(3);      // c1 tambem "muda" (mesmo objeto)

Pegadinha de prova — == entre objetos compara endereços:

Hora h1 = new Hora(12,30,30);
Hora h2 = new Hora(12,30,30);
h1 == h2   // false! ("Diferentes!") mesmo com atributos iguais
Passagem de parâmetro é sempre por valor (como em C). Mas para objeto/array, o valor copiado é o endereço: dá para alterar o conteúdo apontado, não para reapontar a variável de quem chamou. Cópia real exige um método clone().
9

ORIENTAÇÃO A OBJETOS (o que C não tem)

class Funcionario {
    private double salario;                // encapsulamento

    public Funcionario() { ... }             // construtor: mesmo nome, SEM retorno
    public Funcionario(double s) { salario = s; }  // sobrecarga por parametros

    public double getSalario() { return salario; }
    public void setSalario(double salario) {
        this.salario = salario;              // this = objeto corrente
    }
}

Funcionario f = new Funcionario();   // instanciar com new
  • public / private controlam visibilidade.
  • static = pertence à classe, chamado sem instanciar (Math.pow, MyIO.println); atributo estático é único e compartilhado.
  • Herança: class Gerente extends Funcionario.
10

EXCEÇÕES (não existe em C)

Substitui os códigos de erro de retorno do C.

try {
    Integer i = new Integer(args[0]);
} catch (NumberFormatException e) {
    MyIO.println("Erro de formato");
} catch (ArrayIndexOutOfBoundsException e) {
    MyIO.println("Erro de parametro");
} finally {
    MyIO.println("SEMPRE executa");   // limpeza vai aqui
}
  • throw new Exception("msg") → lança.
  • throws na assinatura → repassa para quem chamou (até main pode ter throws Exception).
11

ESTRUTURAS PRONTAS (nativas — não precisa implementar)

Diferente de C, o Java já traz TADs prontos em java.util:

ArrayList<String> lista = new ArrayList<String>();   // array redimensionavel (get rapido)
LinkedList<String> ll = new LinkedList<String>();     // lista dupl. encadeada (insere no meio rapido)
Stack<String> pilha = new Stack<String>();          // push/pop/peek/empty (LIFO)
Queue<String> fila = new LinkedList<String>();       // add/remove/peek (FIFO)

Usam generics <Tipo> para definir o que guardam.
